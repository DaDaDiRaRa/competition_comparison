설계공모 경쟁분석 시스템

설계공모 제안서 PDF를 AI(Anthropic Claude)로 분석해 과거 당선작 패턴을 학습하고, 새로 작성 중인 제안서를 자동으로 진단해 강점·약점·보강 포인트를 짚어주는 사내 도구입니다.

→ 개발자 가이드 (DEVELOPER.md)

개요

이런 분께 추천합니다

PM · 임원
신규 공모 제안서 작성 전, 과거 당선작이 어떤 구성·전략을 따랐는지 데이터로 확인하고 싶은 분
설계 담당자
작성 중인 제안서가 당선 패턴에 얼마나 부합하는지 검토 단계에서 미리 점검하고 싶은 분
리뷰어
같은 공모에 제출된 여러 회사 제안서를 객관적 평가축으로 비교해보고 싶은 분

주요 기능 한눈에 보기

기능입력산출물
데이터 축적과거 공모 지침서 + 여러 회사 제안서 PDF + 당락 결과시설유형별 당선/낙선 패턴 DB
비교분석같은 공모에 제출된 제안서들8개 평가축 채점 + 블라인드 순위 + HTML 리포트
제안서 진단작성 중인 제안서 PDF 1개당선 패턴 대비 강약점 + 보강 포인트 + 진단 리포트
교차 비교서로 다른 공모의 제출물 임의 선택선택된 제출물 일대일 비교 리포트
패턴 뷰어(DB에 쌓인 데이터)당선/낙선 페이지 구성·정량 지표·키워드 통계
TIP · 모든 분석 결과는 HTML 리포트로 저장되어 브라우저에서 열고 Ctrl+P로 PDF 출력할 수 있습니다 (A4 가로 최적화).

1설치

배포 담당자에게서 받은 CompetitionAnalyzer.zip을 원하는 위치(예: 바탕화면, C:\Apps\ 등)에 압축 해제하고, 안의 CompetitionAnalyzer.exe를 더블클릭하면 끝입니다.

  • 별도 설치 불필요 — Python·Node.js 설치 안 해도 됩니다 (모든 의존성이 zip에 포함)
  • 네이티브 윈도우로 실행 — 브라우저 창이 아닌 독립 앱 형태로 열립니다
  • 리포트는 시스템 기본 브라우저로 — 인쇄·PDF 저장이 편하도록 자동 처리

처음 실행 시 주의사항

Windows Defender 경고 · "추가 정보" → "실행" 선택 (서명되지 않은 사내 배포본이라 발생)
WebView2 런타임 · Windows 10/11에는 보통 사전 설치되어 있지만, 없으면 Microsoft 사이트에서 다운로드.
중요 · CompetitionAnalyzer.exe만 따로 빼면 동작하지 않습니다. 반드시 폴더 전체(_internal/ 포함)를 같이 두세요.

2첫 실행 설정

앱을 처음 실행하면 API 키 입력 화면이 나타납니다.

API 키 입력

  1. console.anthropic.com → API Keys → 새 키 생성
  2. 앱 화면에 sk-ant-... 형태의 키 붙여넣기 → 적용
주의 · API 키는 서버 메모리에만 저장됩니다. 앱을 재시작하면 다시 입력해야 합니다.

DB 경로 설정

설정 탭을 열면 DB 경로 항목이 있습니다. 모든 분석 데이터(공모·제출물·리포트·패턴)가 이 경로에 저장됩니다.

  • 미설정 시 기본값: M:\06_설계사업6본부\설계사업6본부 1소\01 개인폴더\16 김정현\KUNWON_COMPETITION_DB (사내 공용 네트워크 드라이브)
    • M:\ 드라이브에 접근할 수 없는 환경에서는 첫 실행 시 자동 생성에 실패할 수 있습니다. 이 경우 설정 탭에서 로컬 경로(예: C:\CompetitionDB)로 변경하세요.
  • 변경: 원하는 경로 입력 후 DB 경로 저장 버튼 클릭. 즉시 적용되며 다음 실행에도 유지됩니다.
  • 팀원과 같은 네트워크 경로를 쓰면 분석 데이터를 자연스럽게 공유할 수 있습니다.

3전체 사용 흐름

경쟁 공모 등록 → 비교분석 실행 → 패턴 학습 → 새 제안서 진단

권장 순서

  1. 경쟁 공모 등록 — 과거 공모의 지침서 + 여러 회사 제안서를 업로드해 데이터 축적
  2. 비교분석 실행 — 저장된 공모 카드에서 버튼 클릭 → AI가 제안서 간 비교 분석
  3. (반복) 여러 공모를 등록할수록 진단 정확도가 올라갑니다
  4. 제안서 진단 — 새로 작성 중인 제안서 PDF를 업로드해 당선 패턴과 비교

4탭별 기능 안내

경쟁 공모 등록 탭

과거 또는 진행 중인 공모의 여러 회사 제안서를 한 번에 등록합니다.

입력 항목

항목설명필수
시설유형공공시설 / 재건축 / 주거 / 업무 등필수
프로젝트번호사내 관리번호 (예: 26-014)필수
프로젝트명공모 이름 (예: 영등포구 신청사)필수
발주처발주 기관명선택
위치대지 위치선택
지침서 PDF공모 지침서 파일선택
제안서 목록 (JSON)각 회사 정보 입력 (아래 참고)필수
제안서 PDF각 회사의 제안서 PDF 파일들필수

제안서 목록 JSON 작성법

[
  { "company": "건축사사무소A", "result": "win" },
  { "company": "건축사사무소B", "result": "lose" },
  { "company": "건축사사무소C", "result": "lose" }
]
  • result 값: win(당선) / lose(낙선) / contracted(수의계약)
  • PDF 파일 업로드 순서와 JSON 순서가 정확히 일치해야 합니다

처리 순서

  1. 데이터 추출 시작 클릭 → AI가 각 PDF를 페이지별로 분류·분석
  2. 완료 후 상단 저장된 공모 목록에 카드가 생성됨
  3. 카드의 비교분석 실행 버튼 클릭 → 제안서 간 AI 비교 분석 실행
  4. 분석 완료 후 비교 리포트 열기 링크로 HTML 리포트 확인
팁 · 데이터 추출과 비교분석은 분리되어 있습니다. 추출 후 바로 비교분석이 자동으로 시작되지 않습니다.

내 프로젝트 등록 탭

자사가 참여한 공모 제안서를 1개씩 등록합니다. 당선/낙선 결과를 함께 기록해 DB에 쌓으면 진단 정확도가 높아집니다.

입력 항목

경쟁 공모 등록과 동일하되, 회사 이름과 결과를 직접 입력합니다.

  • 회사명: 자사 이름 (일관되게 사용)
  • 결과: 당선 / 낙선 / 수의계약

제안서 진단 탭

현재 작업 중인 제안서를 업로드하면 과거 당선작 패턴과 비교해 강점·약점·보강 포인트를 분석합니다.

진단 기준 선택

모드설명
전체 당선 패턴 (자동)DB에 쌓인 해당 시설유형의 모든 당선작 통계 기반
특정 공모 선택비교하고 싶은 공모를 직접 골라 기준 설정

진단 결과 화면

  • 종합점수 (0~10): 당선 패턴 대비 전체 점수
  • 정량 지표 비교 바: 연면적·용적률 등 수치를 당선 평균 / 낙선 평균 / 내 제출물로 나란히 비교
  • 페이지 구성: 실제 페이지 분포
  • 지침서 충족도: 지침서 제출 시 요구사항별 충족 여부
  • 패턴 편차 경고: 당선작 대비 누락된 페이지 유형, 정량 지표 이상 감지
  • 축별 점수: 각 평가 항목 상세 (강점·약점·근거)
  • 보강 포인트: 우선순위 개선 사항

분석 완료 후 진단 리포트 열기 버튼으로 독립적인 HTML 파일로 저장된 리포트를 열 수 있습니다.

교차 비교 탭

서로 다른 공모에서 특정 제출물을 골라 직접 비교합니다.

  • 여러 공모의 제출물을 자유롭게 선택 (체크박스)
  • 교차 비교 실행 클릭 → AI가 선택된 제출물들을 일대일 비교
  • 과거 생성된 교차 비교 리포트는 하단 이전 리포트 목록에서 재열람 가능

설정 탭

API 키 관리

  • 현재 설정된 키 상태 표시 (설정됨 / 미설정)
  • 키 입력 후 키 적용 → 앱 재시작 전까지 유효

모델 설정

  • 기본값: claude-sonnet-4-6
  • 변경 후 모델 설정 저장 클릭

패턴 뷰어

설정 탭 하단에서 시설유형별로 축적된 당선·낙선 패턴 통계를 확인할 수 있습니다.

섹션내용
페이지 구성 통계당선 vs 낙선 평균 페이지 수 (파란 막대 vs 주황 막대)
정량 지표 평균연면적·용적률 등 당선 vs 낙선 수치 비교
컨셉 키워드당선작에 자주 등장한 키워드 (녹색), 낙선 우세 키워드 (적색)
질적 인사이트과거 공모 분석에서 추출한 당선 패턴·낙선 패턴·차별화 요소

패턴 재구축 버튼: 새 공모를 등록한 후 클릭하면 최신 데이터로 패턴 통계가 갱신됩니다.

5용어 설명

용어설명
시설유형공모의 건물 종류 (공공시설, 재건축, 주거, 업무 등). 같은 유형끼리 패턴 비교
공모 (프로젝트)하나의 설계공모 단위. 지침서 + 여러 제출물로 구성
제출물 (submission)한 회사의 제안서 PDF 1개
당선작 패턴DB에 쌓인 같은 시설유형 당선작들의 통계적 특성
낙선 패턴낙선작들의 통계 (당선 패턴과 비교해 경고 기준으로 사용)
비교분석동일 공모 내 제출물들을 AI가 8개 평가축으로 채점·비교
진단단일 제출물을 과거 당선 패턴과 비교해 강약점 분석
리포트AI 분석 결과를 담은 HTML 파일 (브라우저에서 열림, Ctrl+P로 PDF 저장 가능)

6자주 묻는 질문

데이터 추출을 완료했는데 비교 리포트 링크가 없어요.
데이터 추출과 비교분석은 분리되어 있습니다. 저장된 공모 카드에서 비교분석 실행 버튼을 클릭해야 리포트가 생성됩니다.
비교분석 실행 버튼이 없고 "리포트만 재생성" 버튼만 있어요.
이미 비교분석이 완료된 공모입니다. "리포트만 재생성"은 LLM을 다시 호출하지 않고 기존 분석 결과로 HTML만 다시 만듭니다. 비교분석 자체를 다시 하려면 카드 메뉴에서 "비교분석 실행"을 찾으세요.
진단에서 "해당 유형 당선 데이터 없음"이 뜨는데요.
해당 시설유형의 당선작이 DB에 없습니다. 경쟁 공모 등록 또는 내 프로젝트 등록으로 result: "win" 제출물을 먼저 등록하고, 설정 탭 → 패턴 재구축을 클릭하세요.
앱을 재시작했더니 API 키가 사라졌어요.
보안을 위해 API 키는 디스크에 저장하지 않습니다. 앱을 재시작할 때마다 설정 탭에서 다시 입력해야 합니다.
PDF 파일 순서와 JSON 순서를 맞추는 게 어렵습니다.
파일명을 회사명으로 지정해두면 실수를 줄일 수 있습니다. 예: 건축사무소A.pdf, 건축사무소B.pdf. JSON도 같은 순서로 작성.
리포트를 PPT처럼 출력하고 싶어요.
리포트를 브라우저에서 열고 Ctrl+P → "PDF로 저장" 선택. A4 가로 형식으로 최적화되어 있습니다.
API 비용은 얼마나 드나요?
제출물 1개 기준 추출에 약 $0.10~0.30, 비교분석에 약 $0.20~0.50 정도 소요됩니다 (페이지 수·DPI에 따라 다름). 진단은 약 $0.10~0.20. 정확한 비용은 Anthropic 콘솔에서 확인하세요.
앱이 안 뜨거나 갑자기 사라져요. 어디서 원인을 확인하나요?
콘솔 창이 없는 빌드라 에러 메시지가 화면에 뜨지 않습니다. 로그는 %USERPROFILE%\.competition-analyzer\app.log (예: C:\Users\사용자명\.competition-analyzer\app.log)에 기록됩니다. 치명적 오류는 별도 팝업 창으로 알려줍니다. 이 파일을 IT 담당자에게 전달하면 원인 파악이 쉬워집니다.
리포트를 클릭했더니 새 창이 안 열려요.
앱은 target="_blank" 링크를 시스템 기본 브라우저로 보냅니다. 기본 브라우저가 Edge·Chrome 등으로 설정되어 있는지 확인하세요.
색상 테마를 우리 회사 CI에 맞추고 싶습니다.
색상 변경은 소스 코드 수정과 재빌드가 필요한 작업입니다. 사내 IT/개발 담당자에게 DEVELOPER.md의 "테마 / 색상 변경" 섹션을 참고해달라고 요청하세요.
새 버전을 받았어요. 기존 데이터가 사라지나요?
분석 데이터는 DB 경로(설정 탭에서 확인)에 저장되므로 앱 폴더와 무관합니다. 새 버전 폴더로 교체해도 같은 DB 경로를 쓰면 데이터 그대로 유지됩니다.
